# קלפי פורחת

מיצג אינטראקטיבי לבחירות לכנסת ה־26. כל פתק שנכנס לקלפי הופך לפרח. 30 הפתקים הראשונים ממלאים את הקלפי, ואחר כך כל פתק הוא פרח בגינה שמתפשטת בפאטצ'ים. ב־1,000 פתקים (`goal` ב־`config.js`) כל הקרקע ירוקה. המונה חי ומשותף לכל המבקרים. כל מבקר יכול להכניס פתק אחד, עד שהוא מרענן את הדף.

## קבצים

| קובץ | מה יש בו |
|---|---|
| `index.html` | הדף כולו: הקומפוזיציה מה־Figma, הגינה, הרוח, לוח הבדיקה, מחשב ומובייל |
| `config.js` | הגדרות: יעד הפתקים והחיבור ל־Firebase |
| `live.js` | המונה החי (Firebase Realtime Database). מוצא בעצמו את כתובת מסד הנתונים, באירופה או בארה"ב |
| `paper.jpg` | טקסטורת הנייר מה־Figma |
| `database.rules.json` | כללי מסד הנתונים: כל אחד קורא, וכתיבה מותרת רק בתור "הערך הנוכחי + 1" |
| `tools/make-preview.py` | בונה קובץ HTML אחד לתצוגה מקדימה, בלי שרת |

## פרסום ב־GitHub Pages
**Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, תיקייה `/ (root)` → Save**.

כל עדכון ל־`main` עולה לאוויר תוך דקה־שתיים. הכתובת: `https://aki12234-lgtm.github.io/2026_Elections/`.

## Firebase
- הפרויקט: `kalpi-e4081`. ההגדרות כבר ב־`config.js`.
- הכללים מ־`database.rules.json` צריכים להיות מודבקים בלשונית **Rules** של Realtime Database.
- **איפוס המונה:** ב־Firebase Console → Realtime Database → Data, מוחקים את `votes/count`. הדף עצמו לא יכול לאפס, הכללים חוסמים את זה.

## שיתוף
כפתור "שתפו את הקלפי" בפינה הימנית התחתונה. בטלפון הוא פותח את חלון השיתוף של המכשיר, ובמחשב מעתיק את הקישור. אחרי שמכניסים פתק, החץ זז כמה פעמים.

## לוח הבדיקה
מוסיפים `?review` לכתובת. בלוח יש מצבים מוכנים, סליידר, "כל התהליך", רוח ופונטים. כל מה שעושים בלוח הוא סימולציה מקומית ולא נוגע במונה האמיתי. הכפתור "חזרה לחי" מחזיר למונה האמיתי.

## מגבלות ידועות
- ההגבלה של פתק אחד היא לטעינת דף. רענון מאפשר עוד פתק, כמו שהוגדר.
- אין הגנה מבוט שקורא ל־API ישירות. אם זה יהפוך לבעיה, אפשר להוסיף Firebase App Check.
- במכשיר חלש הרוח נכבית אוטומטית והגינה נעצרת, כדי שהדף יישאר חלק.
- אין עדיין תמונת תצוגה לקישור (`og:image`). ייצוא 1200×630 מה־Figma ישפר מאוד את התצוגה בוואטסאפ.
